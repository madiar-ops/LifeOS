## 2. Что возвращает один запрос

| Виджет | Содержимое |
|---|---|
| `goals` | Разбивка по статусам, доля завершённых, просроченные, 5 ближайших целей с прогрессом по задачам |
| `tasks` | Выполнено/осталось, просроченные, на сегодня, на неделю, 5 срочных |
| `finance` | Доходы, расходы, баланс, норма сбережений, топ-5 категорий, тренд за 6 месяцев |
| `health` | Средние сон/шаги/вода, текущий вес и его изменение, среднее настроение, ряд для графика |
| `study` | Материалы, из них с конспектом, заметки, тесты, средний результат |
| `career` | Загружено ли резюме, желаемая позиция, есть ли AI-разбор |
| `recommendations` | 5 свежих рекомендаций |
| `recentFiles` | 5 последних файлов (аватары исключены) |

## 3. Принятые решения

| Решение | Почему |
|---|---|
| **Один агрегирующий endpoint вместо сборки на фронтенде** | Восемь параллельных запросов с мобильной сети — это восемь TLS-рукопожатий и восемь проверок JWT ради одного экрана |
| **Считает БД, а не приложение** | Везде `GroupBy` и агрегатные функции. Ни один виджет не выгружает коллекции целиком ради подсчёта |
| **Запросы идут последовательно, не через `Task.WhenAll`** | EF Core не поддерживает несколько одновременных операций на одном `DbContext` — параллелизм дал бы `InvalidOperationException`, а не ускорение. Готовый ответ, если спросят «почему не распараллелили» |
| **Никаких вызовов AI** | Поход в FastAPI занимает секунды, главный экран обязан открываться мгновенно. Рекомендации берутся из таблицы — те, что уже посчитаны при явных запросах анализа |
| **Отменённые цели исключены из знаменателя `completionRate`** | Отмена — осознанный отказ, а не провал; портить ею статистику неправильно |
| **Валюта выбирается как самая частая у пользователя** | Конвертации курсов в MVP нет, смешивать KZT и USD в один баланс было бы враньём |
| **Тренд всегда за 6 месяцев, независимо от `days`** | График из двух точек бессмыслен |
| **Изменение веса — между первым и последним измерением** | Промежуточные пропуски не должны ломать расчёт |
| **`days` обрезается до 1–365, а не даёт 400** | Дашборд не должен падать из-за опечатки в query-параметре |
| **Аватары исключены из `recentFiles`** | Это не документ пользователя, а элемент интерфейса |
| **Пустой профиль карьеры — не ошибка** | Он создаётся лениво, отсутствие нормально |

## 4. Проверка (чек-лист)

Сценарии 63–67 в `LifeOS.API.http`.

- [ ] `GET /api/dashboard` → **200**, присутствуют все восемь виджетов
- [ ] `completionRate` целей и задач в диапазоне 0..1
- [ ] У целей в `upcoming` заполнены `totalTasks`/`completedTasks`/`progress`
- [ ] `finance.monthlyTrend` содержит точки по месяцам
- [ ] `health.trend` отсортирован от старых к новым
- [ ] `recommendations` содержит записи, созданные в Фазе 6
- [ ] `?days=7` меняет период, `?days=99999` не ломает ответ
- [ ] Без токена → **401**
- [ ] У нового пользователя без данных → **200** с нулями, не 500 ← *важная проверка*
