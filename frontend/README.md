# LifeOS — Frontend

React SPA поверх ASP.NET Core Web API. Фаза 8 плана разработки.

```
React 19 · TypeScript 6 (strict) · Vite · Tailwind CSS 4
React Router · TanStack Query · Axios · react-hook-form + zod · Recharts · lucide-react
```

---

## Быстрый старт

```bash
cd frontend
npm install
cp .env.example .env.development   # проверь адрес API внутри
npm run dev                        # http://localhost:5173
```

Перед первым запуском должен быть поднят backend (профиль `LifeOS.API`) и один раз
выполнена команда, делающая сертификат разработки доверенным:

```bash
dotnet dev-certs https --trust
```

Без неё браузер отклонит запросы к `https://localhost:7001`, и приложение покажет
«Сервер недоступен». Проверить связь можно на странице **Настройки → Связь с API** —
она дёргает публичный `GET /api/ping`.

### Почему порт 5173 зафиксирован

`Cors:AllowedOrigins` в `appsettings.json` бэкенда содержит `http://localhost:5173`.
Если Vite выберет другой порт, браузер отклонит ответы по CORS. Поэтому в
`vite.config.ts` стоит `strictPort: true` — лучше явная ошибка при старте, чем
непонятные отказы в рантайме.

### Если сертификат не удаётся сделать доверенным

Два обходных пути, оба описаны в `.env.example`:

1. HTTP-эндпоинт бэкенда — в Development HTTPS-редирект отключён:
   `VITE_API_BASE_URL=http://localhost:5001/api`
2. dev-proxy Vite — раскомментируй блок `server.proxy` в `vite.config.ts` и поставь
   `VITE_API_BASE_URL=/api`.

По умолчанию прокси НЕ используется: прямое обращение прогоняет в разработке тот же
путь, что и в продакшене (preflight, CORS-заголовки, `Authorization`), поэтому ошибка
в политике CORS обнаружится сразу, а не после деплоя.

## Решения, которые стоит знать

**TypeScript вместо JavaScript.** Backend типизирован (C# records), AI-сервис
типизирован (pydantic). Нетипизированный фронтенд означал бы, что рассинхрон DTO
обнаруживается в рантайме у пользователя, а не при сборке. Включён `strict` и
`noUncheckedIndexedAccess`.

**Токены: access в памяти, refresh в localStorage.** Access-токен нельзя отозвать,
только пережить, поэтому в localStorage его нет — XSS прочитал бы действующий токен.
Refresh лежит в localStorage, иначе пользователь разлогинивался бы при каждом F5;
риск компенсирован ротацией и обнаружением повторного использования на бэкенде.
Идеальный вариант — httpOnly cookie — требует правок backend и отнесён к Фазе 10.

**Обновление токена в единственном экземпляре.** Несколько параллельных запросов при
истёкшем access-токене получили бы 401 одновременно. Наивная реализация отправила бы
несколько `POST /auth/refresh` с одним refresh-токеном, второй попал бы под защиту от
повторного использования и отозвал ВСЮ цепочку токенов. Поэтому обновление одно:
первый запрос его начинает, остальные ждут тот же промис.

**Context + TanStack Query, а не Context вместо него.** Context отвечает за
аутентификацию и тему — значения, нужные всему дереву. Кэш серверных данных,
инвалидация после мутаций и дедупликация запросов — другая задача, и решать её
самописным кодом означало бы написать свой TanStack Query без тестов.

**Дизайн-система на CSS-переменных.** Цвета темы заданы в одном месте, компоненты не
знают, в какой теме отрисованы. Пар `bg-white dark:bg-zinc-950` в коде нет — иначе
каждый новый компонент был бы шансом забыть dark-вариант.

**AI никогда не показывается без уверенности.** Все AI-эндпоинты возвращают один
конверт `AiResultResponse<T>`, и `AiResultCard` отрисовывает его единообразно:
уверенность, объяснение, вклад признаков, версия модели. Порог доверия вычисляет
сервер (`AiService:RecommendationThreshold`), клиент получает готовый флаг
`isConfident` — двух мнений о доверии к модели не бывает.

**Правильные ответы теста на клиент не приходят.** `QuizQuestionResponse` их не
содержит, поэтому подсветить верный вариант до отправки физически невозможно.
Оценка приходит с сервера — именно поэтому ей можно верить.

**Раздела «Администрирование» нет.** На бэкенде `AdminController` не реализован.
Пункт меню, ведущий на несуществующий API, выглядел бы готовой функцией и падал бы
при первом нажатии.

## Деплой (Vercel)

- Build command: `npm run build`
- Output directory: `dist`
- Переменная окружения: `VITE_API_BASE_URL=https://<адрес backend>/api`
- В `Cors:AllowedOrigins` бэкенда добавить домен Vercel — иначе браузер отклонит ответы.

Запасное значение `VITE_API_BASE_URL` — `/api`; оно подходит, только если фронтенд
раздаётся с того же домена, что и API.
